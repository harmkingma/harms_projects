# Shared libraries

Keep a single maintained implementation when multiple projects genuinely need it.

- `esphome`: reusable YAML packages and custom components; include them using
  relative `packages:` / `!include` paths from device configurations.
- `home-assistant`: reusable templates or Python integration packages. Do not
  copy entity-specific automations blindly into multiple installed packages.
- `python`: promote tested reusable Python code into an installable package
  with its own `pyproject.toml`; use an editable path dependency for development.
- `hardware`: common CAD models/footprints; reference originals rather than
  maintaining modified copies in every design.

The water-meter Python library already lives in
`projects\espcam-water\cv\watermeter`. Its add-on is generated by
`projects\espcam-water\tools\stage_addon.py`. Edit the original library, never
the staged `addon\water_meter_reader\app` copy. No artificial shared runtime
library was introduced for unrelated automations or incompatible device boards.

`projects\espcam-water\cv\pyproject.toml` makes this existing implementation an
installable library named `harms-watermeter` (import name: `watermeter`).
The watermeter setup profile installs it editable so tools and future projects
can import it without copying code or changing `PYTHONPATH`. Dependencies are
read from the original `requirements.txt`, not duplicated in packaging metadata.
Calibration files/images remain project data; pass their paths explicitly when
using the installed library outside the original working directory.
